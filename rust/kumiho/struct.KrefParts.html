Expand description

A kref read once: the kernel’s reading plus the textual split.

The kernel’s reading (error_class, base, shapes and the fields below) follows spec/kref/README.md. A kref the kernel refuses has error_class set and no reading: base and every field are None and shapes is empty.

item_name, kind and is_project_root_item describe the first shape the base satisfies; item_name and kind are None when that shape is a space or a project.

The textual split (path, parent, leaf, leaf_name, leaf_kind) does not depend on the kernel’s verdict. KrefParts::get_item_tuple uses it, so a kref this SDK passes through to the backend still yields its request.

The struct is #[non_exhaustive]: it is read through parse_kref, never built by hand, so a later field is not a breaking change.

pub fn get_item_tuple(&self) -> Result<(String, String, String), Error>

The GetItem request (parent_path, item_name, kind) for this kref.

The parent path is / plus everything before the LAST / of the path, so it holds the project and every nested space. The leaf after it is split at its LAST .: item names may contain dots, kinds never do. The query is dropped.

This is the one split used for every item lookup. It depends on the text only, never on the kernel’s verdict.

§Errors

Error::InvalidArgument if the path has no / or its leaf has no .. A leaf without a dot (kref://p/s.v1/x) names a space, not an item.
